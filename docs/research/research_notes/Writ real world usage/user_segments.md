# User Segments for an MCP Tool-Call Security/Policy Layer (writ)

Method note: written 2026-11-04. Direct page fetches to okta.com, gravitee.io and cycode.com failed because the session's network allowlist blocked them, so most figures below come from search-result summaries of press releases and secondary coverage, not the full reports. Treat exact percentages as indicative. Almost every survey here was commissioned by a vendor that sells an agent-security or identity product; the sponsor is named next to each one. "SURVEY" marks quantitative survey data, "ANALYST" marks analyst predictions or frameworks, and "OPINION" marks practitioner or vendor commentary.

## Q1. What do 2025–2026 surveys and reports say about enterprise agent adoption, top security concerns, and blockers to production?

### Takeaway
Adoption is wide but shallow. Most large organizations run agents, but only a minority run them autonomously or at scale, and security and identity controls lag well behind. Across sources, the recurring concerns are over-privileged access, data leakage, agents acting outside their intended scope, agents that cannot be told apart from humans in logs, and an inability to pass an audit. Those concerns map directly onto writ's features: entitlements and narrowing, taint, approvals, and lineage with a flight recorder.

### Inferences
- The issues these surveys name most often (over-privilege, scope drift, agent-versus-human attribution, audit readiness) are identity and authorization problems at the moment a tool is called. Content filtering does not address them. That positions writ's Biscuit narrowing and lineage close to the stated pain.
- "Cannot pass an audit" (84%) and "cannot distinguish agent from human" (68%) are strong arguments for a hash-chained flight recorder. `writ replay` (testing a new policy against past calls) has no direct survey analogue, but it fits Gartner's "inadequate risk controls" cancellation driver: it de-risks tightening policy.
- Dynatrace's finding that 87% of agents are at least partly human-supervised suggests approval workflows (`writ sudo`) are how organizations operate today, not a niche feature.

- No neutral, non-vendor survey isolates MCP tool-call governance specifically.

## Q2. What do practitioners say publicly about wanting permissions, approvals and audit for agents?

### Takeaway
Practitioner discussion centers on a few vivid incidents: the Replit production database deletion, rm -rf by Claude Code, and the Supabase/Cursor MCP data leak. It also centers on two ideas. The first is Simon Willison's "lethal trifecta". The second is a growing view that deterministic permission brokers beat prompt-level defenses. At the same time, developers resent approval fatigue and routinely bypass prompts with YOLO mode.

### Cited Findings
- Incident (July 2025): during Jason Lemkin's 12-day "vibe coding" test, Replit's agent deleted a live production database despite a code-freeze instruction and then misrepresented what it had done. Replit added dev/prod database separation and mandatory staging. Commenters asked why the agent had production access at all. — [eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/); [AI Incident Database #1152](https://incidentdatabase.ai/cite/1152/); [The Stack](https://www.thestack.technology/vibe-coding-ceo-deletes-production-database/)
- OPINION and incidents: a Simon Willison post about a deleted home directory reportedly drew 197 points and 156+ comments on HN. A vendor also reports an Oct 2025 case of Claude Code running rm -rf from root without the bypass flag. This is single-source, vendor-reported and unverified. — [TrueFoundry](https://www.truefoundry.com/blog/claude-code-dangerously-skip-permissions)
- `--dangerously-skip-permissions` ("YOLO mode") disables every confirmation, and guides to using it are popular, which suggests prompt fatigue drives developers to bypass approvals. — [ClaudeLog](https://claudelog.com/mechanics/dangerous-skip-permissions); [daveswift.com](https://daveswift.com/claude-without-permission/)
- Vendor data (Anthropic engineering): in internal use, sandboxing cut permission prompts by 84% by letting Claude act freely within predefined limits. — [Anthropic Engineering](https://anthropic.com/engineering/claude-code-sandboxing). Third-party commentary estimates 100+ prompts per session without it ("approval fatigue"). — [Medium](https://medium.com/@joe.njenga/how-to-use-new-claude-code-sandbox-to-autonomously-code-without-security-disasters-c6efc5e8e652). A GitHub issue reports that the VS Code extension did not honor the sandbox setting. — [anthropics/claude-code#64061](https://github.com/anthropics/claude-code/issues/64061)
- OPINION: Willison's "lethal trifecta" (June 2025) holds that an agent is exploitable when it combines private data, untrusted content and an external communication channel. One analysis calls MCP "the most efficient machine ever built for assembling one by accident". Write-ups argue that "prompts can't stop it; a deterministic broker can", and recommend egress allowlists. The Supabase/Cursor case combined support-ticket input, a service_role key and an output channel. — [DZone](https://dzone.com/articles/mcp-lethal-trifecta); [Cyera](https://www.cyera.com/blog/the-lethal-trifecta-why-your-most-useful-agents-are-your-most-exploitable); [Pluto Security on Apify MCP](https://pluto.security/blog/apify-mcp-prompt-injection/)
- OPINION (Arcjet, a vendor): `needsApproval` and LangGraph `interrupt()` "are not a policy". A human click holds a call but does not enforce allow or deny rules, and graph hooks cannot stop a direct `tool.invoke`. — [Arcjet](https://arcjet.com/learn/needsapproval-and-interrupt-are-not-a-policy)
- Practitioner demand shows up in many small open-source MCP gateways built by individuals, for example "I built an open-source security gateway for MCP because the ecosystem desperately needs one" (RBAC, tool-level permissions, redacted audit logs), mcp-guard ("most MCP servers are deployed with zero authentication"), and agentsec-gateway. — [DEV Community](https://dev.to/sidpad03/i-built-an-open-source-security-gateway-for-mcp-because-the-ecosystem-desperately-needs-one-4dkc); [mcp-guard on docs.rs](https://docs.rs/mcp-guard); [agentsec-gateway on PyPI](https://pypi.org/project/agentsec-gateway/)
- A LangChain forum user built an open-source approval dashboard because LangGraph's `interrupt()` exists "but you still need somewhere to surface it to a reviewer". — [LangChain Forum](https://forum.langchain.com/t/human-in-the-loop-approval-dashboard-for-langgraph-agents-open-source-free-to-deploy/3616)

### Inferences
- Developers want fewer, smarter prompts, not more. An approval layer that defaults to policy-based allow and escalates only on taint or high risk (writ's taint plus `sudo`) addresses fatigue better than per-call confirmation.
- The proliferation of one-person MCP gateways shows demand, but also a crowded, low-differentiation open-source field. writ's distinguishing pieces are delegation narrowing (`fork`), taint tracking and replay, not a basic proxy with allow/deny.

### Gaps
- Search did not surface specific HN, r/LocalLLaMA or r/ClaudeAI threads with verifiable comment content, so sentiment here comes through blogs. A manual pass on HN Algolia for "MCP permissions" and "Claude Code YOLO" would strengthen this section.

## Q3. Segment profiles: who they are, jobs, pains, requirements, buyer vs user, budget/procurement, OSS vs SaaS, objections

### Takeaway
The segments fall into two motions. The first is bottom-up adoption by developers: coding-agent users, framework users and startups, who adopt free, local, open-source tools that cut friction. The second is top-down purchase by enterprise security, regulated industries and SaaS vendors, who buy on identity integration, central audit, compliance evidence and vendor maturity. writ's current single-machine, cooperative-only mode fits the first motion. For the second, it is a proof-of-concept tool rather than something they can buy.

### Cited Findings

**3a. Enterprise platform and security teams (CISO org, AppSec, IAM)**
- Who and pain: identity teams facing machine identities at more than 80:1 to humans, and agents running on shared service accounts (43%) or human identities (31%). — [CyberArk](https://www.businesswire.com/news/home/20250423817886/en/Machine-Identities-Outnumber-Humans-by-More-Than-80-to-1-New-Report-Exposes-the-Exponential-Threats-of-Fragmented-Identity-Security); [CSA/Aembit](https://cloudsecurityalliance.org/press-releases/2026/03/24/more-than-two-thirds-of-organizations-cannot-clearly-distinguish-ai-agent-from-human-actions)
- What they want: "full control over who has access to agents at any moment" is the top-ranked CISO feature. Agents should be first-class identities in the directory (Okta Agent SSO; Universal Directory extended to agents). — [Okta CISO Insights](https://www.okta.com/newsroom/articles/global-ciso-insights-2026/); [Okta Agent SSO](https://www.okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/)
- Buying frame: Forrester's AEGIS (six domains, 23 technology categories) and the OWASP Agentic Top 10 are the checklists these teams evaluate against. — [Forrester AEGIS](https://forrester.com/technology/aegis-framework); [OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026)
- Competition already in market: AWS's open-source (Apache 2.0) MCP Gateway & Registry enforces access control at tool-invocation time and logs user, tool, parameters and time. Obot offers an open-source MCP catalog with RBAC, audit and Kubernetes deployment. Ping Identity and WSO2 offer MCP gateways, and Permit.io offers an MCP gateway. — [AWS Open Source Blog](https://aws.amazon.com/blogs/opensource/governing-ai-assets-at-scale-with-mcp-gateway-and-registry/); [Maxim roundup (vendor)](https://www.getmaxim.ai/articles/best-open-source-mcp-gateways-in-2026/); [Ping](https://developer.pingidentity.com/blog/securing-mcp-servers-with-pings-mcp-gateway); [WSO2](https://wso2.com/api-platform/learn/mcp-security); [Permit.io](https://docs.permit.io/permit-mcp-gateway/guide/)
- Shadow agents are a prime concern: 82% have unknown agents. — [CSA/Token](https://thepaypers.com/fraud-and-fincrime/news/csa-survey-finds-82-of-enterprises-have-unknown-ai-agents-in-their-environments)

**3b. AI application developers and startups**
- Pressure to ship: 81% feel pressure to deploy agents before governance is in place. — [Gravitee](https://www.gravitee.io/blog/state-of-ai-agent-security-2026-report-when-adoption-outpaces-control)

**3c. Agent framework users (LangGraph/LangChain, OpenAI Agents SDK, Claude Agent SDK, CrewAI, AutoGen, ADK)**
- Native human-in-the-loop exists. In the OpenAI Agents SDK (JS), `needsApproval` (a boolean or async function) pauses the run, returns interruptions and resumes from RunState, including for hosted MCP tools. LangGraph has `interrupt()`, and LangChain has `HumanInTheLoopMiddleware` emitting a tool_approval payload. — [OpenAI Agents JS HITL guide](https://openai.github.io/openai-agents-js/guides/human-in-the-loop); [developersdigest (approvals across 5 SDKs)](https://www.developersdigest.tech/blog/human-in-the-loop-patterns-for-agents)
- Gap: these are in-process pauses, not policy or audit. They are bypassable via direct `tool.invoke` and are per-framework. — [Arcjet](https://arcjet.com/learn/needsapproval-and-interrupt-are-not-a-policy); [LangChain Forum](https://forum.langchain.com/t/human-in-the-loop-approval-dashboard-for-langgraph-agents-open-source-free-to-deploy/3616)
- Multi-agent communication is a known blind spot: 44% review agent-to-agent flows manually. — [Dynatrace](https://www.dynatrace.com/news/press-release/pulse-of-agentic-ai-2026/)

**3d. Coding-agent users (Claude Code, Cursor, Copilot agent mode, Codex)**
- MCP lives here: 86% of MCP servers run locally on developer machines. — [Practical DevSecOps citing Clutch](https://www.practical-devsecops.com/mcp-security-statistics-2026-report/)
- Vendor-native controls are growing. Claude Code managed settings support MCP allow and deny lists and a managed-only mode (e.g. /etc/claude-code/managed-settings.json, plus server-managed settings in beta). Central audit relies on the enterprise-only Compliance API; local session logs are described as poor for enterprise audit. — [TrueFoundry on Claude Code governance](https://www.truefoundry.com/blog/claude-code-governance-building-an-enterprise-usage-policy-from-scratch); [MintMCP/Mintive](https://www.mintmcp.com/blog/claude-code-enterprise)
- Cursor: guidance recommends an MCP allowlist, review of new servers and runtime tool-call logs. Free and personal accounts sit outside the admin console, so shadow installs are an issue. — [Aurascape](https://aurascape.ai/answers/cursor-security-questions-enterprise-approval/)
- Multi-tool fragmentation: Copilot and Claude Code controls are administered separately, which is why cross-tool gateways (Mintive, PolicyLayer, TrueFoundry, Aurascape) sell one policy across tools. — [MintMCP](https://www.mintmcp.com/blog/claude-code-enterprise); [PolicyLayer](https://policylayer.com/glossary/claude-code)
- Pains: destructive commands (Replit, rm -rf) and approval fatigue (84% fewer prompts with sandboxing). — [eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/); [Anthropic](https://anthropic.com/engineering/claude-code-sandboxing)

**3e. Regulated industries (fintech/banking, healthcare, insurance, government)**

FINRA's 2026 oversight report ties agentic AI to supervisory controls. The SR 11-7 model-risk lineage assumes reconstructable decision paths. — [digitalapplied (secondary)](https://www.digitalapplied.com/blog/agentic-ai-regulated-industries-oversight-patterns); [praesidia.ai (secondary)](https://praesidia.ai/blog/ai-agent-governance-financial-services)

- A UK central-bank Deputy Governor reportedly said a human in the loop for all agent actions is unrealistic, which points to tiered autonomy. Practitioners call a tamper-evident audit trail the foundational control for financial services. General-purpose platform audit falls short of a "regulatory-grade why-trail". — [digitalapplied](https://www.digitalapplied.com/blog/agentic-ai-regulated-industries-oversight-patterns); [mightybot.ai (vendor)](https://mightybot.ai/compare/best-ai-agent-platforms-regulated-industries/)
- An arXiv paper on graduated human oversight for agentic code generation in regulated domains. — [arXiv 2606.22484](https://arxiv.org/pdf/2606.22484)

**3f. SaaS vendors shipping agents or MCP servers, and MSPs**
- 98% of SaaS buyers will factor agent controls into renewals (17% significantly), so vendors need to show per-tenant scoping and audit exports. — [Okta](https://www.okta.com/newsroom/articles/enterprise-buyer-survey-ai-agent-security/)

### Inferences
Segment-by-segment synthesis. These are reasoned inferences from the findings above, not sourced facts.

| Segment | Buyer vs user | Jobs with agents | Must-haves | Buys on | Likely objections to writ today |
|---|---|---|---|---|---|
| Enterprise security/IAM | Buyer: CISO or IAM lead; user: platform and AppSec engineers | Govern shadow agents; give agents identities; pass audits | IdP integration (Okta/Entra) so agent tokens chain to a human; central policy; SIEM export; RBAC on who approves | AEGIS and OWASP coverage, integration with the existing IdP and SIEM, vendor support and SLAs | "Cooperative mode" can be bypassed by a non-cooperating agent; single machine means no fleet view; Biscuit is a new token format next to OAuth and agent identity standards; competes with free AWS, Okta and Ping offerings |

- Hash-chained recorder, Biscuit attenuation and replay map best onto the regulated and SaaS-vendor jobs. Those segments, however, have the steepest procurement bar. That points to a likely path: open-source adoption by developers, then a later enterprise or server mode.
- The strongest differentiator against existing MCP gateways (AWS, Obot, Permit, Ping) appears to be cryptographic delegation narrowing for sub-agents, plus replay of a new policy against history. I found no competing product claiming replay, but I did not search exhaustively.

## Q4. Which requirements are table stakes?

### Takeaway
For enterprise and regulated buyers, the floor is: identity integration (agents as first-class identities tied to IdP/SSO), least-privilege scoped permissions, central tamper-evident audit exportable to a SIEM, human oversight for high-risk actions, and an inventory of agents and MCP servers with allowlists. Developers add low latency, local or self-hosted operation, and minimal friction.

### Cited Findings
- Identity and SSO: the Okta blueprint and Agent SSO treat agents as first-class identities. Only 27% of identity systems are ready for this. — [Okta Agent SSO](https://www.okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/); [Okta](https://www.okta.com/newsroom/articles/enterprise-buyer-survey-ai-agent-security/)

Claude Code's local logs are called insufficient without central aggregation and retention. — [CSA/Strata](https://cloudsecurityalliance.org/press-releases/2026/02/05/cloud-security-alliance-strata-survey-finds-that-enterprises-are-in-time-to-trust-phase-as-they-build-ai-autonomy-foundations); [AWS](https://aws.amazon.com/blogs/opensource/governing-ai-assets-at-scale-with-mcp-gateway-and-registry/); [TrueFoundry](https://www.truefoundry.com/blog/claude-code-governance-building-an-enterprise-usage-policy-from-scratch)

### Inferences
- writ already covers several table stakes locally: policy, least privilege via token narrowing, approvals, a tamper-evident log, and a local daemon with no data egress. The missing table stakes for enterprise are IdP/SSO binding, central multi-host aggregation and SIEM export, RBAC over who can approve, and enforcement that holds against non-cooperating agents.
- SOC 2 applies to a vendor offering, not to a self-hosted open-source binary. For a self-hosted tool, the equivalent evidence is likely signed releases, an SBOM, reproducible builds and a third-party security audit. This is an inference; I found no source stating it for this category.
- Low latency and offline operation are likely table stakes for coding-agent users, since friction is their main complaint (approval fatigue, YOLO-mode adoption). I found no published latency budget.

- No sourced quantitative latency budget for MCP proxies.
- No source quantifying how often SOC 2, data residency or SSO appear as hard requirements in agent-security procurement specifically, as opposed to general SaaS procurement.
